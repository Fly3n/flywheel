# 微信文章拉取 (wx-fetch)

用于精准、稳定地从微信公众号文章链接（`https://mp.weixin.qq.com/s/...`）抓取并提取标题、作者、发布时间和清洗后的正文内容。

## 核心原理与坑点防护

微信公众号文章针对普通爬虫有严格的防刷拦截（会返回“环境异常，去验证”页面）以及本地代理 SSL 握手冲突。本 Skill 内置了确定性 Python 脚本，采用以下防护机制：
1. **伪造客户端 User-Agent**：模拟 iOS 微信客户端内置浏览器（MicroMessenger）。
2. **代理隔离**：在抓取请求中自动清空环境变量中的 `http_proxy`/`https_proxy`，避免本地代理导致的 `SSL: UNEXPECTED_EOF_WHILE_READING` 报错。
3. **HTML 标签清洗与解密**：精准提取 `<h1 id="activity-name">`、`<a id="js_name">` 和 `<div id="js_content">`，剥离 `<script>`/`<style>`，格式化为 Markdown 友好的纯文本。

## 使用方式

### 1. 抓取文章并复用缓存

先把本 Skill 目录作为工作目录，再运行内置的确定性 Python 脚本。不要假设 Skill 安装
在某个用户的固定绝对路径。

```bash
# 默认先读缓存；未命中时抓取并自动缓存完整正文
python scripts/fetch_wechat_article.py "<URL>"

# 输出 JSON；仍会自动使用或更新缓存
python scripts/fetch_wechat_article.py "<URL>" --json -o article.json

# 明确忽略缓存并重新抓取
python scripts/fetch_wechat_article.py "<URL>" --refresh
```

### 2. 参数说明

* `<URL>`：微信公众号文章完整链接（必需）。
* `-o, --output <path>`：保存结果的目标文件路径（可选）。
* `--json`：以标准 JSON 结构输出（包含 `title`, `author`, `publish_time`, `url`, `content` 字段）。
* `--refresh`：忽略已有缓存并重新抓取、覆盖缓存。
* `--cache-dir <path>`：覆盖默认缓存目录，仅用于测试或显式指定其他位置。

完整清洗正文默认按 URL 缓存在 `~/.wx-fetch/cache/articles/`。后续处理同一 URL 时优先读取
缓存，不重复请求微信；只有用户要求刷新、缓存不完整或原文已更新时才重新抓取。`-o` 是额外
导出，不影响自动缓存。缓存写入失败时仍可基于本次正文回答，但必须说明后续讨论可能需要
再次抓取，不能把“已抓取”表述成“已缓存”。

## 交互与输出规范

用户只提供链接或泛化要求读取文章时，先显示已取得的标题、作者和发布时间，再用四个简短
部分建立认知：

1. **这是什么**：说明文章类型、核心主题或要解决的问题，以及最重要的结论或信息。
2. **怎么展开**：用一条简短链路概括文章逻辑，不复述完整目录。
3. **有什么用**：只说明文章能为哪些读者或场景提供什么认知、方法或信息；没有用户背景时
   使用“如果你正在……”的条件表达，不默认列举文章没有覆盖的内容。
4. **内容浓缩**：选择最能支撑前述认知的核心观点、方法、证据或结论，通常不超过五点，
   每点只表达一个信息，帮助用户决定下一步追问，不做逐段摘要或全文改写。

默认使用几段短句，不主动展开完整步骤、所有案例或延伸知识。用户已经带着具体问题提供文章
时，先直接回答问题，只补理解答案所需的背景，不强制套用完整框架。作者动机、因果关系、
实际效果或用户适配度没有正文证据时不推测。

除非用户明确要求“沉淀/导入外部笔记或知识库”，否则默认仅用于对话剖析与讨论，不写入其他知识库，
也不主动推销导入。自动文章缓存只服务本次及后续问答，不属于知识库沉淀。
