# 微信文章拉取 (wx-fetch)

用于精准、稳定地从微信公众号文章链接（`https://mp.weixin.qq.com/s/...`）抓取并提取标题、作者、发布时间和清洗后的正文内容。

## 核心机制

针对公众号反爬拦截与本地代理环境，内置确定性脚本提供免配抓取：
1. **客户端模拟与代理隔离**：模拟微信移动端客户端发起请求，并在抓取时自动隔离本地代理环境变量，避免 SSL 握手异常。
2. **正文提取与清洗**：定位文章元数据与主体内容，剥除样式与脚本，格式化为 Markdown 友好的段落纯文本。
3. **本地持久缓存**：默认按 URL 进行哈希持久化缓存，避免对相同链接重复发起网络请求。

## 使用方式

以本 Skill 目录作为工作目录运行内置脚本，或直接指定脚本路径：

```bash
# 默认先读缓存；未命中时抓取并自动缓存完整正文
python scripts/fetch_wechat_article.py "<URL>"

# 输出 JSON；仍会自动使用或更新缓存
python scripts/fetch_wechat_article.py "<URL>" --json -o article.json

# 明确忽略缓存并重新抓取
python scripts/fetch_wechat_article.py "<URL>" --refresh
```

### 参数说明

* `<URL>`：微信公众号文章完整链接（必需）。
* `-o, --output <path>`：保存结果的目标文件路径（可选）。
* `--json`：以标准 JSON 结构输出（包含 `title`, `author`, `publish_time`, `url`, `content` 字段）。
* `--refresh`：忽略已有缓存并重新抓取、覆盖缓存。
* `--cache-dir <path>`：覆盖默认缓存目录，仅用于测试或显式指定其他位置。

完整清洗正文默认按 URL 缓存在 `~/.wx-fetch/cache/articles/`。后续处理同一 URL 时优先读取缓存，不重复请求微信；只有用户要求刷新、缓存不完整或原文已更新时才重新抓取。`-o` 是额外导出，不影响自动缓存。缓存写入失败时仍可基于本次正文回答，但必须说明后续讨论可能需要再次抓取，不能把“已抓取”表述成“已缓存”。

## 交互与输出规范

用户只提供链接或泛化要求读取文章时，拒绝被动长篇摘要与目录复述。先显示已取得的标题、作者和发布时间，再按以下结构建立高密度认知：

1. **这是什么（本质定性）**：用一两句话点破其本质，定位其在行业或技术坐标中的位置，说明解决的核心问题或核心论点。
2. **怎么展开（逻辑链路）**：抽离一条极简推演链（如：`痛点/瓶颈 → 破局机制 → 验证结果`），不复述完整目录。
3. **场景与延伸（原文主张 vs AI 独立发散）**：
   - **原文核心场景**：作者主推、已验证的典型落地场景或读者群体。
   - **发散思考（AI 延伸）**：跳出原文，重点探讨作者未提及的跨界玩法、生态结合点或潜在新拼图可能。
4. **批判性研判与边界**：指出其适用边界、不可行场景、工程/认知成本或潜在漏洞，不盲从吹捧。
5. **追问切入点**：给出 2~3 个不同维度的切入支点（技术细节、实践落地、商业模式或与已有系统结合），方便用户选择下一步方向。

默认使用短句与高密度段落，不主动展开完整步骤、所有案例或冗长改写。用户已经带着具体问题提供文章时，先直接回答该问题，只补理解答案所需的必要背景，不强制套用完整框架。原文已确认事实与 AI 发散推演必须明确区分，无直接证据时不臆测作者动机或客观效果。

除非用户明确要求“沉淀/导入外部笔记或知识库”，否则默认仅用于对话剖析与讨论，不写入其他知识库，也不主动推销导入。自动文章缓存只服务本次及后续问答，不属于知识库沉淀。
